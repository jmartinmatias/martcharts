# Chart catalog

Generated by `npm run catalog` from the view registry and the example widgets. Do not edit by hand.

57 views. Every one has a self-contained spec in [catalog/](../catalog/): the data is inlined and already reshaped, so it draws in any page with no server.
Open [catalog/index.html](../catalog/index.html) through any static server to see them all.

## Use one in any project

```html
<script src="martcharts.iife.js"></script>  <!-- your copy of dist/martcharts.iife.js; installing is in frameworks.md -->
<fft-widget src="catalog/bar.json" actions="csv image"></fft-widget>
```

Not sure which chart? `recommendCharts(rows)` (or MCP `fft_recommend_charts`) ranks the ones that suit your data, each with a filled view. Or swap the data for yours: keep the `view` block, change `data` (`inline` rows, a `url`, or a `fn` in code) so each row has the fields the view names. `validateSpec(spec, rows)` says what is missing. In a bundler, `import { createWidget } from "martcharts"` instead. Agents do the same through the MCP server ([mcp.md](mcp.md)): `fft_list_charts` lists this catalog, `fft_get_chart` returns one entry with its starter spec, `fft_validate_spec` checks a spec, `fft_create_widget` saves one.

## `anomalies`

An anomaly tracker: one thin lane per metric over time, the band it was expected to stay in as a faint fill, the expected value as a hairline, the actual as a line, and every day it stepped outside the band as a flagged dot. The lanes with the most anomalies come first, each ending with its latest value and a count. For watching a dozen measures at once and seeing which ones need a look.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `x` | date | yes | Field with the date or period of each reading. |
| `metric` | category | yes | Field naming the measure each row belongs to; each measure is one lane. |
| `value` | number | yes | Field with the reading. |
| `expected` | number |  | Field with the value expected that day, drawn as a hairline through the band. |
| `low` | number |  | Field with the bottom of the expected band. Needs high too. |
| `high` | number |  | Field with the top of the expected band. Needs low too. |
| `flag` | category |  | Field that is true on anomalous readings (true, 1, "yes"). Flagged readings draw as filled dots in the alert color. Without it, readings outside the band are flagged. |

**Answers**: Which measures stepped out of their expected range, and when?

**How to read it**: Each thin lane is one measure, along date. The line is what happened; the faint band is where it was expected to stay, with a thin line for the expected value. A filled dot marks an anomaly, a reading that stepped out of line. The lanes with the most anomalies come first, and each ends with its latest value and its count. Here, 6 readings were flagged across 6 of 6 measures; Net new money stepped out most, once, last on Oct 10, 2026 at 1M.

## `area`

A line with a soft filled area down to zero, for a trend where the amount itself matters. Best with one or two series, or stacked: composition over time, each series a band on top of the ones before. As a stream, the bands flow around a center line, for how a mix shifts over time.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `x` | date | yes | Field for the ordered axis, usually a date or period. |
| `y` | number (one or more) | yes | Field or fields for the values. Each field is one series. |
| `forecast` | category |  | Field that is true on forecast rows. From the last actual on, lines draw dashed in a softly shaded zone labelled Forecast, and the tooltip marks those rows. On an area the forecast's wash is fainter too. Unstacked areas only. |

**Settings**: `stacked`, `highlight`, `endLabels`, `reference`, `band`, `curve`, `annotations`. All options with defaults are in [blocks.md](blocks.md#area).

**Answers**: Where is cash heading next?

**How to read it**: The filled shape shows how cash changes month by month: higher means more. The dashed part is a forecast, a careful guess about what comes next; the shaded area shows how sure it is: the wider, the less sure. Here, it went from €4.2M in Oct 2025 to €5.4M in Sep 2026, and is expected to reach €6.2M by Mar 2027, most likely between €4.5M and €8.2M.

## `bar`

Vertical bars comparing amounts across categories. Several y fields draw grouped bars.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `x` | category | yes | Field for the categories along the horizontal axis. |
| `y` | number (one or more) | yes | Field or fields for bar heights. Each field is one series. |
| `lines` | number (one or more) |  | Field or fields drawn as lines over the bars, on the same axis, for example a target. Never a second axis. Under one target line (a field named target, plan, goal, budget or quota), bars on the wrong side of it (see goodWhen) are drawn outlined and keyed Below target. |
| `compare` | number |  | Field drawn as a wider, quieter column behind each bar, on the same axis, for a comparison such as last year or the plan. The key names it by its label and the tooltip gives its value. One y series, unstacked. |

With a group field, one list per client under its own heading. For meetings, calls, trades, campaigns and complaints in one scroll.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `date` | date | yes | Field with when the event happened. |
| `title` | category | yes | Field with the event in a few words. |
| `kind` | category |  | Field with the kind of event (Meeting, Call, Trade); each kind takes a color and a letter, keyed. |
| `note` | category |  | Field with a second, smaller line under the title. |
| `amount` | number |  | Field with an amount to write at the right of the event, where there is one. |

## `lifecycle`

Stage swimlanes: one row per item on a shared date axis, each stage drawn from its date to the next in a deepening tint of one hue, a tick at every stage date, and the last reached stage running on faintly while its next date is unknown. A today line, a status pill at the row's end, and an impact that sets the row's thickness. For where each regulation stands, from proposal to application.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `label` | category | yes | Field naming each row. |
| `stages` | date (one or more) | yes | Date fields in lifecycle order, such as proposed, adopted, inForce, applies. A later date may be missing: the row then runs on from its last known stage. |
| `group` | category |  | Field that gathers rows under a heading, such as topic. |
| `status` | category |  | Field written as a small pill at the row's end, such as In force or Consultation. |
| `impact` | number |  | Field from 1 to 5 that sets each row's thickness: the higher the impact, the thicker the row. |

**Settings**: `today`, `highlight`. All options with defaults are in [blocks.md](blocks.md#lifecycle).

**Answers**: Where does each stand stand, from proposed to applies?

**How to read it**: Each row is one entry, read left to right in time. Each colored stretch is one stage, proposed, adopted, in force and applies in turn, deeper as it goes; a tick marks where each began, and a faint stretch is a stage still running. The upright line is today, the word at the end of a row is its status, a thicker row means a higher impact. Here, 9 of 12 regulations have reached applies. AMLR moved last, to applies on 2027-07-10.

## `whitespace`

The cross-sell map (whitespace analysis): one cell per client and product, filled where the client holds the product, outlined where it is an opportunity (tinted by how likely), blank where the client is not eligible. Each row ends with its penetration (3 of 8) and the revenue still to win; each column ends with how many hold it and how many could. Rows sort with the most to sell first.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `row` | category | yes | Field naming each row, usually the client. |
| `column` | category | yes | Field naming each column, usually the product. |
| `state` | category | yes | Field saying whether the row holds the column, could (an opportunity), or is not eligible. See states. |
| `score` | number |  | Field with how likely each opportunity is, 0 to 100 (a propensity). An opportunity cell's tint strengthens with it. |
| `value` | number |  | Field with the money in each cell: revenue where held, potential where open. Written in the tooltip; the open cells' sum ends each row. |

**Settings**: `states`, `sort`. All options with defaults are in [blocks.md](blocks.md#whitespace).

**Answers**: Which clients could take more products, and which ones first?

**How to read it**: Each row is one client and each column one product. A filled square means they already have it, an outlined square means they could (the stronger its tint, the more likely), and a small dot means it is not for them. The end of each row counts what they hold and what is still to win. Here, 20 cells are held and 17 are open; Aldana Holdings has the most to win, €253K.

## `xray`

A client x-ray: one client on one card, from its first row. The name and a detail line, a grid of key facts, the products it holds as pills (held in color, not held outlined), a share-of-wallet meter, a small trend, quiet warning flags and a short list of next best actions. For a client page, a pre-meeting brief or a relationship manager's cockpit.

**Data it needs**: one row per mark, with these fields (names are yours; the view options point at them).

| Option | Field holds | Required | What it is |
| --- | --- | --- | --- |
| `label` | category | yes | Field with the client's name. |
| `detail` | category |  | Field for the line under the name, such as the segment or the relationship manager. |
| `facts` | number (one or more) |  | Up to six fields shown as small labelled figures: assets, revenue, products held, client since. |
| `holdings` | category (one or more) |  | True/false fields, one per product, drawn as a strip of named pills: held in color, not held outlined. |
| `wallet` | number |  | Field with the share of wallet, 0 to 1, drawn as a meter with its percent. |
| `trend` | category |  | Field whose value is a list of numbers (revenue by month, say), drawn as a small trend with its first and last values written. |
| `flags` | category |  | Field whose value is a list of short warnings, shown as quiet amber pills: ["No contact in 90 days", "Fee leakage"]. |
| `actions` | category |  | Field whose value is a list of next best actions, shown as a short checklist. |

**Answers**: How does this entry stand right now, and what should we do next?

**How to read it**: This card is one entry, top to bottom: the key numbers, the products in color are the ones they hold, the bar is how much of their share of wallet is with us, the small line is the recent trend, the amber pills are things to watch, and the list is what to do next. Here, Aldana Holdings holds 3 of 8 products and has a share of wallet of 41%.
